# Architecture Decision Records

このディレクトリは **「なぜそう作ったか」** を残す場所。使い方や現行ルールは置かない。

| 置き場所 | 内容 | 性質 |
|---|---|---|
| `README.md` | ライブラリの使い方 | **常に最新だけ** |
| `CLAUDE.md` | 今どう開発するか(規約・手順) | **常に最新だけ**。古い記述は上書きする |
| `docs/adr/` | なぜそう決めたか(判断・根拠・却下案) | **追記のみ**。過去の判断を消さない |
| `docs/specs/` | 実装前の設計書 | 作成時点のスナップショット |

---

## 運用ルール: 1テーマ1ファイル・追記方式

**1決定1ファイルにしない。** テーマ単位でファイルを作り、決定が変わったら同じファイルに追記する。

理由: 1決定1ファイルは正統な ADR 方式だが、小規模なライブラリでも年に数十個まで増えて管理不能になる。テーマ単位なら **5〜8 ファイル**で数年運用できる。

### 追記のしかた

- 新しい決定は **ファイル末尾に日付付きで追記**する
- 過去の決定は**書き換えない**。撤回する場合は「## YYYY-MM-DD: 〜を撤回」と新セクションを足し、旧セクションの冒頭に `> ⚠️ この判断は YYYY-MM-DD に撤回(下記参照)` を1行足すだけにとどめる
- 「現在の結論」はファイル冒頭の **## 現在の決定** に置き、ここだけは上書きしてよい

### ファイルを新設する基準

既存テーマに入らない**独立した判断領域**が生まれたときだけ。迷ったら既存ファイルに追記する。

## 記述上の注意

このリポジトリは公開されている。**実環境のアドレス・ホスト名・アカウント名を書かない。**
例示が必要なときは RFC 5737 の文書用アドレス(`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`)か
`<hyperv-host>` のようなプレースホルダを使う。CI がプライベートアドレスの混入を落とす
(`.github/workflows/_security-scan.yml` の `no-private-addresses`)。

## アーカイブ方針

**当面は不要。** 上記の追記方式なら急激には増えない。

将来 15 ファイルを超えたら、以下の条件を**すべて**満たすものだけ `docs/adr/archive/` へ移す。

- その判断の対象が実装から消えている
- 現行の判断に影響しない(他の ADR から参照されていない)
- 1 年以上更新がない

移動する際は索引に「(archived)」として行を残し、リンクは切らない。**経緯を辿れなくすることが最大の損失**なので、容量を理由に消さない。
